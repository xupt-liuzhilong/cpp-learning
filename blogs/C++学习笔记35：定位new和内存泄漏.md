# C++学习笔记35：定位new和内存泄漏

## 一、普通 new 做了什么？

前面已经知道，普通的 `new` 会完成两件事：

```cpp
1. 申请空间
2. 调用构造函数
```

例如：

```cpp
A* p = new A(10);
```

可以理解为：

```cpp
先申请一块能存放 A 对象的空间
然后在这块空间上调用 A 的构造函数
```

也就是说，普通 `new` 把**内存申请**和**对象构造**放在一起完成。

但是有些特殊场景下，空间已经提前准备好了，我们只想在这块已有空间上调用构造函数。

这时就要用到**定位 new**。

------

## 二、什么是定位 new？

定位 new，也叫 placement new。

它的作用是：

> 在已经分配好的内存空间上，显式调用构造函数。

语法：

```cpp
new(已有空间地址) 类型(构造参数);
```

例如：

```cpp
new(p) A(10);
```

含义是：

```cpp
在 p 指向的那块空间上，调用 A 的构造函数，并传入参数 10。
```

注意，定位 new **不会重新申请空间**，它只负责在已有空间上构造对象。

------

## 三、定位 new 的基本示例

```cpp
#include <iostream>
#include <cstdlib>
using namespace std;

class A
{
public:
    A(int x)
        : _x(x)
    {
        cout << "A(int)" << endl;
    }

    ~A()
    {
        cout << "~A()" << endl;
    }

    void Print()
    {
        cout << _x << endl;
    }

private:
    int _x;
};

int main()
{
    // 1. 先申请一块原始空间
    void* p = malloc(sizeof(A));

    // 2. 在这块空间上显式调用构造函数
    A* pa = new(p) A(10);

    pa->Print();

    // 3. 手动调用析构函数
    pa->~A();

    // 4. 释放原始空间
    free(p);

    return 0;
}
```

运行结果类似：

```cpp
A(int)
10
~A()
```

这里的过程是：

```cpp
malloc 只申请原始空间
定位 new 在这块空间上调用构造函数
手动调用析构函数清理对象
free 释放原始空间
```

------

## 四、定位 new 和普通 new 的区别

普通 new：

```cpp
A* p = new A(10);
```

它完成：

```cpp
申请空间 + 调用构造函数
```

定位 new：

```cpp
void* p = malloc(sizeof(A));
A* pa = new(p) A(10);
```

它只完成：

```cpp
在已有空间上调用构造函数
```

二者对比：

| 方式                | 是否申请空间 | 是否调用构造函数 |
| ------------------- | ------------ | ---------------- |
| 普通 `new A(10)`    | 是           | 是               |
| 定位 `new(p) A(10)` | 否           | 是               |

所以定位 new 的核心价值是：

> 把“申请空间”和“构造对象”这两步拆开。

------

## 五、定位 new 后为什么要手动调用析构函数？

普通 `delete` 会做两件事：

```cpp
1. 调用析构函数
2. 释放空间
```

但是定位 new 使用的空间不一定来自普通 `new`。

比如：

```cpp
void* p = malloc(sizeof(A));
A* pa = new(p) A(10);
```

这块空间是 `malloc` 申请的。

所以不能直接：

```cpp
delete pa; // 不推荐，空间来源不匹配
```

应该手动拆开：

```cpp
pa->~A();  // 手动调用析构函数
free(p);  // 释放 malloc 申请的空间
```

也就是说：

```cpp
用定位 new 构造对象后，需要手动调用析构函数。
空间怎么申请的，就用对应方式释放。
```

如果是 `malloc` 申请的，就用 `free`。

如果是 `operator new` 申请的，就用 `operator delete`。

------

## 六、定位 new 的应用场景

普通开发中，定位 new 用得不多。

它主要出现在一些更底层的场景：

```cpp
1. 内存池
2. 预分配缓冲区
3. 共享内存
4. 需要分离内存分配和对象构造的场景
```

比如内存池中，程序可能提前申请一大块空间。

之后创建对象时，不再频繁向系统申请内存，而是从这块空间中取一小块，然后用定位 new 构造对象。

这样可以减少频繁申请和释放内存带来的开销。

初学阶段不需要自己实现内存池，但要知道：

```cpp
定位 new 是用来在已有空间上构造对象的。
```

------

## 七、什么是内存泄漏？

动态内存申请后，如果不再使用，却没有释放，就会造成**内存泄漏**。

例如：

```cpp
void Func()
{
    int* p = new int[10];
}
```

这个函数结束后，局部指针变量 `p` 会销毁。

但是 `new int[10]` 申请的堆空间不会自动释放。

由于地址已经丢失，这块空间就无法再被释放。

这就是内存泄漏。

正确写法：

```cpp
void Func()
{
    int* p = new int[10];

    delete[] p;
    p = nullptr;
}
```

------

## 八、内存泄漏的危害

对于很短的小程序来说，即使忘记释放，程序结束时操作系统通常会回收整个进程的资源。

所以有些简单练习中，内存泄漏不一定马上表现出来。

但是对于长期运行的程序，问题就很严重。

例如：

```cpp
服务器程序
操作系统服务
后台进程
游戏服务端
数据库程序
```

如果每次运行都泄漏一点内存，时间久了就可能导致：

```cpp
程序占用内存越来越大
系统变慢
其他程序申请不到内存
程序崩溃
```

所以内存泄漏是 C/C++ 动态内存管理中非常重要的问题。

------

## 九、常见内存泄漏场景

### 1. 申请后忘记释放

```cpp
int* p = new int[10];

// 忘记 delete[] p
```

------

### 2. 中途 return 导致没有释放

```cpp
void Func()
{
    int* p = new int[10];

    if (/* 某个条件 */)
    {
        return; // 直接返回，p 没有释放
    }

    delete[] p;
}
```

这种情况在实际代码中很常见。

解决思路是：返回前确保释放，或者后面学习 RAII、智能指针来管理资源。

------

### 3. 指针被覆盖，原空间丢失

```cpp
int* p = new int[10];

p = new int[20]; // 原来那块 int[10] 的空间丢了
```

此时第一块空间没有释放，而且地址已经找不到了。

正确做法：

```cpp
delete[] p;
p = new int[20];
```

------

### 4. new 和 delete 不匹配

```cpp
int* p = new int[10];

delete p; // 错误
```

应该写：

```cpp
delete[] p;
```

虽然这不只是内存泄漏问题，还可能造成未定义行为，但在对象数组中很容易导致析构不完整。

------

## 十、释放后的指针建议置空

释放空间后，指针变量本身还保存着原来的地址。

例如：

```cpp
int* p = new int(10);

delete p;
```

此时 `p` 仍然保存原地址，只是那块空间已经无效。

如果继续使用：

```cpp
cout << *p << endl; // 错误
```

就是释放后继续访问。

所以建议：

```cpp
delete p;
p = nullptr;
```

这样后面即使判断：

```cpp
if (p != nullptr)
{
    cout << *p << endl;
}
```

也能避免继续访问已释放空间。

------

## 十一、如何减少内存泄漏？

初学阶段先做到：

```cpp
1. new 和 delete 配对
2. new[] 和 delete[] 配对
3. malloc 和 free 配对
4. 申请后及时释放
5. 释放后指针置空
6. 注意函数中途 return 的情况
```

后面学习 C++ 更深入内容时，还会接触：

```cpp
RAII
智能指针
容器类
```

比如 `vector`、`string`、`unique_ptr` 等，它们可以帮助我们减少手动管理内存的错误。

------

## 十二、小结

本篇主要学习了定位 new 和内存泄漏。

需要记住：

1. 普通 `new` 会申请空间并调用构造函数；
2. 定位 new 不申请空间，只在已有空间上调用构造函数；
3. 定位 new 的语法是 `new(p) A(参数)`；
4. 定位 new 常用于内存池、预分配空间等场景；
5. 使用定位 new 后，需要手动调用析构函数；
6. 空间怎么申请，就应该用对应方式释放；
7. 内存泄漏是指申请的动态内存没有正确释放；
8. 短程序泄漏影响可能不明显，长期运行程序危害很大；
9. 常见泄漏原因包括忘记释放、中途 return、指针覆盖、释放方式不匹配；
10. 初学阶段要养成动态内存申请和释放配对的习惯。

定位 new 让我们更清楚地看到：对象的创建其实可以拆成两步——**内存分配**和**对象构造**。而内存泄漏则提醒我们：只要手动申请资源，就必须考虑如何正确释放。
